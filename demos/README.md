# Project List

Demos are numbered in rough order of complexity — start at `01-` if you're new to Strata, and work up toward the real-world examples at the higher end.

| # | Demo | Project | Description |
|---|------|---------|-------------|
| 01 | [hello-agent](01-hello-agent) | `01-hello-agent.csproj` | Single-node graph: reads `Name` from state, writes a `Greeting`. `StateGraph` → `.Compile()` → `.RunAsync()` with a sync handler, nothing else. |
| 02 | [tool-calling](02-tool-calling) | `02-tool-calling.csproj` | An async node dispatches a source-generated `[StrataTool] add` method through `IStrataToolProvider` (STRATA-SPEC-003), passing a `ToolCallContext.From(ctx)` and the run's token; the tool reads its caller from a `ToolCallContext` parameter that the generator keeps out of the manifest (`design/20-Tool-Dispatch-And-Registry.md`). |
| 03 | [llm-tool-calling](03-llm-tool-calling) | `03-llm-tool-calling.csproj` | A live model, OpenAI or a local one such as Ollama (through `Microsoft.Extensions.AI`'s `IChatClient`) decides to call the source-generated `add` tool from demo 02, and Strata's own agent loop (`StrataAgent<string>` + `AddAgentNode`, `design/44-LLM-Integration.md`) declares it, dispatches the call through a `ToolRegistry` with the agent's id and the model's call id in the `ToolCallContext`, sends the result back and returns the answer. Requires `OPENAI_API_KEY`. |
| 04 | [multi-node-graph](04-multi-node-graph) | `04-multi-node-graph.csproj` | A linear chain (`.AddEdge(...)`) feeding a conditional branch (`.AddConditionalEdge(...)`, first match in declaration order, a plain edge last as the "else") that reconverges on a shared node — `CalculateSubtotal` -> `ApplyDiscount` -> bulk/standard shipping branch -> `FormatReceipt`; both branches are run and checked. |
| 05 | [hitl-interruption](05-hitl-interruption) | `05-hitl-interruption.csproj` | Human-in-the-loop interruption with typed signals (STRATA-SPEC-002, `design/21-Typed-Human-Signals.md`): two wire transfers freeze at `.AddInterruptBoundary(..., onReject: "CancelWireTransfer")` in a real SQLite file; after a simulated restart a new store instance lists what is waiting, refuses a string override that doesn't fit a decimal before touching the checkpoint, approves one transfer with a typed override (`ExecuteWireTransfer` reads the reviewer from `NodeContext.Decision`) and rejects the other onto its reject route. |
| 06 | [token-streaming](06-token-streaming) | `06-token-streaming.csproj` | A model node (`.AddModelNode(...)`) streams a live model's answer (OpenAI, or a local one such as Ollama) through `RunStreaming` as `Token` chunks via `StrataChat`, while the node gets the whole answer back as one `ChatResponse`. Then a request for a model that doesn't exist gets a real provider 4xx, which fails the node fatally: one attempt, and its `RecoveryPolicy` doesn't retry (STRATA-SPEC-001, `design/44-LLM-Integration.md`). Requires `OPENAI_API_KEY`. |
| 07 | [graph-validation](07-graph-validation) | `07-graph-validation.csproj` | A document review pipeline built twice from the same nodes: an unguarded retry loop plus a typo in an edge makes `.Compile()` throw `GraphCompilationException` with `STRATA_ERR_DANGLING_EDGE`, `STRATA_ERR_ORPHAN` and `STRATA_ERR_UNGUARDED_CYCLE`; guarding the retry edge and fixing the typo makes it compile and run, with a branch-and-rejoin inside the guarded loop that the validator accepts (STRATA-SPEC-004). |
| 08 | [error-recovery](08-error-recovery) | `08-error-recovery.csproj` | `.AddFallibleNode(...)` + `RecoveryPolicy`: a flaky payment gateway is retried with exponential backoff (`WithBackoff`), a 503's `Retry-After` hint sets the wait (capped at max), the fallback reads why from `NodeContext.LastFailure`, failed attempts' partial state is rolled back, and a fatal error leaves a durable `Failed` checkpoint in SQLite that is resumed once the cause is fixed (`design/04`, `design/25`). Waits run on a `FakeTimeProvider`. |
| 09 | [cross-language-interop](09-cross-language-interop) | `09-cross-language-interop.csproj` | Freeze a wire-transfer graph in one runtime and resume it in the other through a single shared SQLite checkpoint log: run `-- freeze` here then `resume` from the Rust twin (or the reverse). Each node stamps which runtime ran it, and the `strata` CLI reads the same file. Two modes: `freeze` / `resume`. All four directions verified on 0.9. |
| 10 | [parallel-fan-out](10-parallel-fan-out) | `10-parallel-fan-out.csproj` | `.AddParallelGroup(...)` with async branches: a trip planner asks three simulated services (flights, hotels, weather) concurrently and merges the results with a reducer. Shows real overlap (peak in flight, wall time ≈ slowest branch), a merge order that follows branch *declaration* order rather than completion order, group-level failure (the first failure cancels the siblings still running; a transient blip retries *all* branches, a fatal one falls back on the pre-group state), and streaming branches attributed to `<group>/<branch>` (`design/14-Parallel-Execution.md`). Options and joins are demo 17. |
| 11 | [backpressure](11-backpressure) | `11-backpressure.csproj` | An async flood node emits 20 000 tokens with `EmitTokenAsync(token, ct)` through `RunStreaming` against three bad consumers, proving the 1024-chunk channel *pauses* the node instead of dropping tokens: a stalled consumer freezes it at exactly 1023 tokens (plus the engine's `NodeStart` = 1024 queued chunks) with nothing lost once it drains; a slow consumer never lets it get more than 1024 tokens ahead; an abandoned one is released by cancelling the run, which ends `Cancelled` with a resumable checkpoint (a sync `EmitToken` producer is released too, when the run ends) (STRATA-SPEC-001, `design/17-Async-Execution.md`). |
| 12 | [pluggable-storage](12-pluggable-storage) | `12-pluggable-storage.csproj` | One graph, one scenario, four storage backends — in-memory, SQLite, **Postgres** and **Redis** — through the same code: freeze a wire-transfer graph, drop every connection, resume from a fresh one, read a chat history back. Redis (a list per thread, no tables) is the proof the store interfaces aren't SQL-shaped. Also shows concurrent writers, the 0.9 `OpenAsync`/`ConnectAsync` stores, delta checkpoints written by one store and read whole by another without them (`design/41-Checkpoint-Efficiency.md`), and a cross-runtime hand-off through Postgres or Redis with the Rust twin. Requires Docker (`docker compose up -d --wait`). Modes: matrix (default), `freeze` / `resume`. |
| 13 | [subgraph-composition](13-subgraph-composition) | `13-subgraph-composition.csproj` | `.AddSubgraph(...)`: a support desk whose `Triage` supervisor routes tickets, with ordinary conditional edges, to two specialist agents that are *compiled graphs of their own* with their own state types — one of which nests a third graph. Shows a child's own routing and loops running inside one parent node, a child recovering itself, the parent's `RecoveryPolicy` re-running the *whole* child, a fatal error two levels down whose `Failed` checkpoint nests each child's so a resume re-enters at the failed node (`design/15`, `design/16`), a human's approval inside an agent (typed override to the child's state, a decision only the child's level sees), and an exported definition that carries every child's graph (`design/22`). |
| 14 | [graph-ci-gate](14-graph-ci-gate) | `14-graph-ci-gate.csproj` | `strata graph validate` as a CI gate: seven graphs built in code are exported with `StateGraph<T>.ToDefinition()` (which, unlike `.Compile()`, accepts a broken graph) and checked as a folder by the real `strata` binary. Shows a failing pull request (every file reported, exit 1) with the CLI and `.Compile()` returning identical diagnostics, the trap of exporting a compiled graph's `Topology`, an interrupt boundary with a reject route in the file (`"interrupt"`, `1.6.0`, and `strata graph view`), the fix (exit 0), and what a gate that can't check does (exit 2, including a hand-edited boundary). The Rust twin writes byte-identical files for all seven. Needs the `strata` CLI binary from the [GitHub Release](https://github.com/datalium/strata/releases/tag/v0.9.0-preview.1), on the `PATH` or in `STRATA_BIN` (STRATA-SPEC-004, `design/48-Boundaries-In-Definitions.md`). |
| 15 | [async-and-cancellation](15-async-and-cancellation) | `15-async-and-cancellation.csproj` | Async handlers with `NodeContext` (thread, qualified path, attempt, run id, metadata) and run-level inputs in `RunOptions`, in a vendor-payment run. A per-node `SetTimeout` turns a hung attempt into a transient failure that a retry recovers. A blocking sync handler is abandoned, not waited for (and its late side effect still lands). A run cancelled by token or deadline returns `Cancelled` with a resumable `cancelled` checkpoint, and a resume re-enters only the stopped node. Timeouts run on a `FakeTimeProvider` (`design/17-Async-Execution.md`). |
| 16 | [loop-circuit-breaker](16-loop-circuit-breaker) | `16-loop-circuit-breaker.csproj` | STRATA-SPEC-004's `MaxNodeHops`: a guarded re-planning loop in a meeting scheduler compiles fine but never converges on bad input. `Compile(new CompilationOptions { MaxNodeHops = 12 })` stops it with `HopLimitExceeded` and a `failed` checkpoint (`error_kind` `hop_limit`, `strata.hops`). Retries aren't hops, the count survives interrupts and resumes by a freshly built graph, and `RunOptions.MaxNodeHops` raises or lowers the limit for one run (`design/24-Loop-Circuit-Breaker.md`). |
| 17 | [parallel-joins](17-parallel-joins) | `17-parallel-joins.csproj` | Parallel group options (`design/26-Parallel-Group-Controls-And-Joins.md`): three carriers quote for a parcel under `FirstSuccess` (losers cancelled with `LostRace`), `FirstMatching(predicate, description)` (with a `KeepSucceeded` fallback to every answer), `Quorum(2)` and a `MaxConcurrency = 1` failover chain; `JoinDecided` and `BranchCompleted.Reason` say who won and why the rest stopped. Also when an unmet join fails transiently (a retry could still meet it) or fatally, and an `AddParallelGroupWithOutcomes` tracking board with `BranchTimeout`, `MaxConcurrency` and `KeepSucceeded` on a fake clock. |
| 18 | [map-fan-out](18-map-fan-out) | `18-map-fan-out.csproj` | `.AddMap(...)` (`design/27-Map-Fan-Out.md`): an invoice audit runs a compiled child graph once per invoice line read from the state, at most 8 at a time by default (never unbounded), keyed by line id (`AuditLines/<line>/<node>`). Shows the lists that fail the map before anything starts (duplicate key, `/` in a key, empty key, over `MaxItems`), a failing line's fatal or transient kind (with its retry hint) becoming the map's, a retried map re-running every line, an outcomes reducer with `KeepSucceeded`, and `.Compile()` refusing a child with an interrupt boundary. |
| 19 | [waits-and-timers](19-waits-and-timers) | `19-waits-and-timers.csproj` | Event waits, durable timers and ending a thread (`design/28`, `29`, `42`): orders that wait for a payment signal, a fraud review that times out to a route, a pickup timer woken by `WakeDueAsync` or by your own `ResumeStreaming(LevelSignals.Due)`, `EndAsync`, and a `timed_out` end, all on a SQLite file and a fake clock. |
| 20 | [durable-execution](20-durable-execution) | `20-durable-execution.csproj` | `CheckpointPolicy.EveryNode` and a real crash: the program starts itself as a worker process, which charges a card inside `Charge` and is killed before the node commits, leaving the thread `running` in a SQLite file with its lease unreleased. The parent shows a running thread refusing `ResumeAsync`, `RecoverStaleAsync` skipping it while the dead worker's lease is live and recovering it once it expires, and at-least-once execution: `Charge` runs again with the same `NodeContext.IdempotencyKey` and `IsRecovery` set, so a gateway that deduplicates by key charges once. Also `RecoveryCount.Of` and the `Recovered` event (`design/33-Durable-Execution.md`). |
| 21 | [thread-leases](21-thread-leases) | `21-thread-leases.csproj` | Two workers, one thread, `RunOptions.Lease = new LeaseOptions(owner, ttl)` on fake clocks: the second worker is refused while the lease is live (`held by 'worker-a' until ...`), and a slow node keeps its lease by renewing every ttl / 3. Without leases a stale worker saves over the new owner's draft; with them, a worker whose lease expired and was taken over ends `Cancelled(LeaseLost)` and writes nothing, whether its fenced save or its next renewal finds out. Shows the `LeaseAcquired` / `LeaseLost` run events (`design/32-Thread-Leases.md`). |
| 22 | [graph-identity](22-graph-identity) | `22-graph-identity.csproj` | Graph identity (`design/31-Graph-Identity.md`): `GraphId`/`GraphVersion` on every checkpoint, v1 threads refused by v2 with nothing written, another graph refused, `Owns`, listing by version, and `Migrate` adopting a v1 thread (renamed field and node) into v2, shown in the SQLite rows. |

## Adding a demo

1. Create the project under `demos/NN-demo-name/` (e.g. `dotnet new console -o demos/NN-demo-name`)
2. Add a `<Project Path="demos/NN-demo-name/NN-demo-name.csproj" />` entry to the `/demos/` folder in [`../Strata.Demos.slnx`](../Strata.Demos.slnx)
3. Add versionless `<PackageReference>`s to the Strata packages it uses (see root [README.md](../README.md#dependencies-on-strata))
4. Add a row to the table above
